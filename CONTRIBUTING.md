# Contributing

Contributions are welcome. This project has one unusual rule that matters more than
any style guideline, so it comes first.

## The one rule: never invent biology

Every biological value in this repository must be traceable to a citable source, or
be explicitly labelled as an assumption.

Concretely, a change is not acceptable if it:

- adds a biological parameter without a citation;
- fills a gap with a plausible-looking default instead of leaving it empty and
  reporting it;
- collapses a distinction the source makes (for example flattening "takes up GABA from
  neighbours" into plain "GABA");
- attaches an inferred or predicted value without recording that it is inferred.

If you genuinely need a number that nobody has measured, that is fine — invent it
deliberately, mark it `Confidence.ASSUMED`, and add a row to
[`docs/model_assumptions.md`](docs/model_assumptions.md) saying what it is, why you
chose it, and how it could be improved. The problem is never the assumption; it is the
silent assumption.

The check that enforces this is:

```bash
python tools/inspect_connectome.py --dataset witvliet_2021_7 gaps
```

Anything your change adds to that output needs a citation behind it.

## Setup

```bash
python -m venv .venv
.venv/Scripts/python -m pip install -e ".[dev,viz]"    # Windows
# .venv/bin/python -m pip install -e ".[dev,viz]"      # macOS / Linux
.venv/Scripts/python -m pytest
```

Python 3.12 or newer. The committed data means the tests run offline on a fresh clone;
eight tests that re-parse raw sources skip until you run `tools/fetch_datasets.py`.

## Before opening a pull request

```bash
python -m pytest
python -m ruff check .
python -m mypy common worm tools --ignore-missing-imports
python tools/generate_neuron_reference.py --check
```

All four must pass. CI runs the same commands.

## Adding a dataset

See [`worm/README.md`](worm/README.md) for the step-by-step. The short version:

1. Add it to `worm/data/sources.toml` with URL, SHA-256, licence and citation.
2. Add its **published** totals to `worm/data/reference_totals.toml`, citing where those
   numbers came from. A dataset with no independent oracle cannot be trusted, and
   `build_datasets.py` refuses to write one without `--allow-unverified`.
3. Write an importer producing an **unannotated** connectome. Anatomy only.
4. Cite it in `docs/references.md` and `DATA_LICENSES.md` — a test enforces the first.

Do not commit raw source files. `tools/fetch_datasets.py` downloads them; see
[DATA_LICENSES.md](DATA_LICENSES.md) for why.

## Code conventions

- Type hints on everything; `mypy` is configured with `disallow_untyped_defs`.
- Line length 100, enforced by `ruff`.
- Comments explain *why*, especially where a choice encodes a biological or
  provenance decision. The gap-junction storage convention in
  `common/data/schemas.py` is the model to follow.
- Prefer an understandable implementation over a dependency. This project deliberately
  runs on `numpy`, `networkx` and `openpyxl` and nothing else; do not add a large
  framework to implement a small equation.
- Derived data is regenerated by a committed script, never edited by hand. If a CSV in
  `worm/data/` needs to change, change the generator.

## Language

Behavioural descriptions, not mentalistic ones. Say "the model reversed after the
stimulus", not "the worm decided to flee". Be careful with *intention*, *desire*,
*fear*, *decision*, *consciousness*.

Accurate framing for this work: *biologically derived nervous-system model*,
*connectome reconstructed from a biological specimen*, *embodied connectome*,
*biologically constrained neural controller*, *closed-loop sensorimotor simulation*.

Not accurate: *uploaded brain*, *resurrected animal*, *preserved consciousness*,
*digital organism*. A connectome is anatomy, and anatomy is not a mind.

Philosophical questions about what would be needed to bridge that gap are genuinely
interesting and welcome — labelled as questions.
